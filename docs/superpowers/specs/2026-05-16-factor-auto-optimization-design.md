# 因子权重优化系统

## 目标

手动触发因子权重优化：回测各因子在当前权重附近的组合，找出年化收益最高且回撤可控的组合，生成变更报告。权重替换由独立指令执行，不自动生效。

## 与 FactorMonitor 的关系

本方案 + merge 方案（`quick_monitor`）共同替代 FactorMonitor + FactorTuner：

| FactorMonitor 功能 | 替代者 |
|---------------------|--------|
| 每日因子 IC 监控 | `quick_monitor()` — 每日自动，纯观测 |
| 因子变化检测 + 历史回放 | 不需要（IC 自然反映） |
| 记录 picks JSON + backfill | 不需要 |
| FactorTuner 自动调优 | 本方案 — 手动触发，数据驱动 |

## 触发

- **人为手动触发**，不做 cron 定时
- 必须在**休盘时间**运行（周末、交易日收盘后至次日开盘前），盘中禁止
- CLI 入口：
  - `python main.py --factor-optimize` — 运行优化，生成报告
  - `python main.py --factor-apply <report_path>` — 应用报告中的权重到 .env

## 三步流程 + 四个护栏

### Step 1: 单因子筛选

- 对每个因子单独回测（权重 100%，其余为 0）
- 回测窗口：最近 **60 个交易日**
- 模式：支持 intraday / postmarket（因子数不同，分别优化）
- 过滤条件：最大回撤 ≤ **-20%**
- 排序：按年化收益率从高到低
- **不固定数量**：所有通过筛选的因子都是候选。若超过 **6 个**，取 Top 6（控制搜索规模 ≤ 15,625 组合）
- 负 IC 因子直接排除（报告标注「IC 为负，已排除」）

### Step 2: 权重扰动搜索

- 以**当前 .env 中的实际权重**为基准（非固定网格）
- 每个候选因子的权重选项：`[当前-10, 当前-5, 当前, 当前+5, 当前+10]`，钳位到 [5, 35]
- 全组合搜索，回测窗口 60 个交易日
- 过滤条件：最大回撤 ≤ **-20%**

### Step 3: 最优推荐

- 取 Step 2 中满足回撤约束且年化收益最高的组合
- **兜底**：若 -20% 无任何组合满足，自动放宽至 **-25%** 并记录警告
- 若 -25% 仍无结果，跳过本轮并在报告中说明
- **不自动替换权重**，仅输出报告

### 护栏 A: 最小改进阈值

- 最优组合年化收益需比当前组合高 **≥ 1%** 才推荐变更
- 差值 < 1% → 视为噪声，报告中标注「改进幅度不足（+0.X%），建议保持当前权重」

### 护栏 B: 稳定性检查

- 每次优化结果保存到 `discovery_reports/factor_optimization/latest.json`
- 下次运行时，对比每个因子的推荐方向
- 若同一因子**连续两次推荐方向相反**（前次+5，本次-5 或前次-10，本次+5）：
  - 该因子本轮不调整，保持原权重
  - 报告标注「⚠️ 方向不稳定（前次+X，本次-X），本轮跳过」
- 方向一致的因子正常推荐
- 若是首次运行（无历史），跳过此检查

### 护栏 C: 当前组合基线对比

- 报告始终包含「当前组合」vs「最优组合」的完整对比：
  - 年化收益、最大回撤、夏普比率、胜率
  - 每个因子的 IC Rank（1日/5日）
- 方便判断是否值得执行 `--factor-apply`

### 护栏 D: 因子相关性提示

- Step 2 后检查推荐加权重的因子间的相关性（基于历史得分序列的 Pearson 相关）
- 若两个同时加权的因子相关性 > 0.75：
  - 报告标注「⚠️ A 与 B 相关性 0.XX，同时加权重可能过拟合同一类信号」
  - 不阻断推荐，仅提示

## 权重替换（独立指令）

`python main.py --factor-apply <report_path>`

- 读取优化报告，提取新权重
- 写入 `.env` 中的因子权重配置项（替换前备份原值）
- 打印变更摘要

## 不改的

- 不修改因子本身（因子代码不变）
- 不新增/删除因子
- 不改变回测引擎逻辑（复用现有 `FactorBacktestEngine`）
- 不做 cron 自动触发（纯手动）
- 不引入负权重（负 IC 因子在 Step 1 直接排除）
